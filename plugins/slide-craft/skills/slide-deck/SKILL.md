# 발표 자료 만들기

장표를 바로 만들지 않는다. 아래 순서로 간다. 유료 서비스(Gamma, Canva 등)에 내용을 올리지 않는다.

## 1. 입력 확인

아래를 대화와 파일에서 찾는다. 없는 것만 한 번에 묻는다. 사용자가 "끝까지 진행"이라고 했으면 기본값으로 간다.

| 항목 | 기본값 |
|------|--------|
| 청중과 그들이 이미 아는 것 | 같은 조직의 개발자 |
| 발표 시간 | 20분 → 본문 10~12장 |
| 산출물 형식 | 단일 HTML. PPTX 는 사용자가 요청했거나 남이 PowerPoint 에서 고쳐야 할 때만 |
| 사내 템플릿(`.pptx`·`.potx`) | 있으면 HTML 이어도 열어서 색·글꼴·머리 구조를 그대로 가져온다. PPTX 는 템플릿 위에서만 만든다 |
| 재료 문서 | 대화에서 가리킨 파일 |
| 발표자의 말투 표본 | 있으면 읽고 따른다 |

## 2. 재료

- 재료 문서에서 **실제 수치·식별자·화면**을 뽑는다. 가상의 예시 숫자와 가상 화면을 만들지 않는다.
- 재료에 없는 사실이 필요하면 지어내지 말고 "확인 필요" 목록에 올린다.
- 뽑은 사실마다 출처 파일을 적어 둔다. 6단계 대조에 쓴다.

## 3. 스토리라인

장표를 만들기 전에 `storyline.md` 를 쓴다. 장마다 세 줄이다.

```
## 3. 같은 지적을 매일 새 업무로 만들지 않는다      ← 제목은 주장 한 줄
- 근거: 지문 = 저장소 + 파일 + 관점 + 코드 한 줄 / 상태 신규·잔존·재발
- 모양: 표 (판별 기준 4개)                           ← 흐름도·표·큰 숫자·캡처·코드 중 하나
```

- 제목만 이어 읽어도 발표 내용이 전달돼야 한다. "개요", "소개", "현황" 같은 명사 제목은 주장으로 바꾼다.
- 장의 모양은 내용을 따른다. 흐름은 흐름도, 비교는 표, 수치 하나는 큰 숫자, 실물은 캡처.
- 한 장에 주장 하나. 넘치면 장을 나눈다.
- 재료가 이미 장 단위로 나뉜 문서여도 그대로 옮기지 않는다. 표는 비교가 본질인 장에만 남기고, 나머지는 아래 표대로 바꾼다. 표가 전체의 3분의 1을 넘으면 다시 짠다.

| 내용의 성격 | 모양 |
|-------------|------|
| 독립된 결정·원칙 여러 개 | 카드 격자. 고른 것은 크게, 버린 대안은 취소선, 근거는 아래 |
| 순서, 되돌이 | 흐름도. 되돌아가는 길은 색이 다른 선으로 |
| 수치 하나 | 큰 숫자. 전체 대비면 점·막대로 비율을 같이 보인다 |
| 양쪽 대비 | 좌우 대칭, 가운데에 항목 이름, 핵심 행 하나만 강조 |
| 이전과 이후 | 흐린 색(이전) → 진한 색(이후) 화살표 행 |
| 여러 대상 비교 | 표. "없음"은 흐리게, 우리 행만 채운다 |
| 기간 | 길이가 기간에 비례하는 막대 |
| 요청·결정 | 번호 붙은 짙은 패널 |
- 스토리라인을 사용자에게 보이고 넘어간다. "끝까지 진행" 지시가 있으면 보이기만 하고 계속한다.

## 4. 다이어그램

- 발표 전체를 꿰는 그림 한 장을 먼저 만들고, 절마다 해당 구간만 강조해 다시 쓴다.
- PPTX 면 네이티브 도형으로 그린다(발표 직전까지 고칠 수 있다). 복잡하면 `.drawio` 나 Mermaid 로 만들어 SVG·PNG 로 넣고 원본 파일을 같이 둔다.
- 상자 안 글은 6단어 이하. 화살표에는 무엇이 넘어가는지 적는다.

**아키텍처 그림.** 같은 크기 사각형에 글을 채워 쌓지 않는다.

- 계층을 띠로 나누고 왼쪽에 계층 이름을 둔다. 위에서 아래로 진입점 → 제품 → 공통 계층 → 기반 → 배포 순서.
- 위계를 셋으로 둔다: 계층 띠, 그 안의 구성 요소 카드, 카드 안의 세부 칩. 크기·색 농도·글자 굵기가 위계마다 달라야 한다.
- 축·역할마다 색을 하나씩 정해 끝까지 쓴다. 발표의 핵심 요소 한 곳만 강조색으로 채운다.
- 구성 요소 이름 옆에 아이콘을 둔다. 계층 사이에는 화살표와 무엇이 넘어가는지 적은 이름표를 둔다.
- 요소 안에 순서가 있으면(개발 → 배포) 나열하지 말고 흐름으로 그린다.
- 짙은 바탕에 반투명 카드가 밝은 바탕보다 계층 구분이 잘 보인다.

## 5. 제작과 렌더링 검수

**HTML (기본).** 이 스킬 폴더의 `assets/deck-base.html` 을 산출물 위치로 복사해 `<section class="slide">` 를 채운다. 무대 축소·넘기기·인쇄용 CSS·아이콘과 위 표의 모양별 구성 요소가 들어 있고, 파일 머리 주석에 구성 요소 목록이 있다. 맞는 구성 요소가 없으면 같은 변수와 간격으로 새로 만든다. 처음부터 다시 쓰지 않는다.

**디자인 언어.** 색과 글꼴을 지어내지 않는다.

- 사용자가 템플릿을 주면 열어서 디자인 가이드 장과 실제 쓰인 색(`srgbClr` 빈도)을 뽑아 `:root` 변수에 넣고, 머리 구조(덱 이름·절·쪽 번호, 소제목, 제목, 구분선)를 따른다.
- 템플릿이 없으면 `deck-base.html` 의 기본값을 쓴다. GS네오텍 2026 템플릿 값이다: 진청 `#1419AB`, 밝은 청 `#3C41E6`, 연보라 `#999DFF`, 옅은 바탕 `#E6E7FF`, 강조 주황 `#FDB24D`, 글꼴 Pretendard(제목 SemiBold, 본문 Regular·Medium). 이 PC 에 `~/Downloads/2026_PPT Template.pptx` 가 있으면 PPTX 는 그 위에서 만든다.
- 축·역할이 둘이면 청색과 주황으로 나눠 표지부터 끝 장까지 같은 색을 쓴다.
- Pretendard 는 웹폰트로 받고 오프라인에서는 맑은 고딕으로 떨어지게 둔다.

**PPTX.** `pptx` 스킬의 절차를 따른다. 템플릿의 레이아웃을 먼저 고르고 구조(추가·삭제·순서)를 내용보다 먼저 맞춘다. 템플릿 없이 좌표로 사각형과 표를 놓아 만들지 않는다 — 그렇게 만든 결과물은 디자인이 없다.

**규칙.**

- HTML 은 1920×1080 기준 제목 48~56px, 본문 22~26px, 가장 작은 글자 17px. PPTX 는 제목 36~44pt, 본문 14~16pt 이상.
- 여백은 바깥 0.5인치(72px) 이상, 본문 좌측 정렬.
- 내용이 화면 높이의 3분의 2 아래에서 끝나면 글자와 행 높이를 키워 채운다.
- 한글 폰트는 발표 PC 에 있는 것으로 지정한다(맑은 고딕, Pretendard 등). 없는 폰트를 지정하지 않는다.
- 차트는 네이티브 차트로 넣는다.
- 장당 강조 한 곳. 말로 할 내용은 발표자 노트로 옮긴다.

**검수.** 만든 뒤 반드시 이미지로 렌더링해 장마다 본다. HTML 은 헤드리스 Chrome 으로 장마다 찍는다(`chrome --headless=new --window-size=1920,1080 --screenshot=<경로> "file:///...#번호"`, Windows 에서는 경로를 `C:/...` 꼴로 준다). PPTX 는 LibreOffice 로 PDF 로 바꾼 뒤 `pdftoppm -jpeg -r 150`. 글자 넘침·겹침·잘림·빈 칸·남은 placeholder·깨진 한글을 찾아 고치고, 고친 장만 다시 렌더링한다. 넘침이 없다고 끝내지 않는다 — 표만 이어지는 장, 아래가 빈 장, 위계가 안 보이는 장도 고친다. 렌더링 도구가 없으면 검수를 못 했다고 보고에 적는다 — 했다고 쓰지 않는다.

## 6. 정제와 사실 대조

1. `humanize-ko` 스킬로 글과 화면을 정제한다.
2. 정제 뒤 장표의 모든 수치·식별자·조건을 2단계에서 적어 둔 출처와 대조한다. 바뀌었거나 빠진 것을 되돌린다.

## 7. 보고

- 산출물 경로, 장 수.
- 렌더링 검수를 했는지, 몇 번 돌렸는지.
- "확인 필요" 목록: 재료에 없어 비워 둔 사실, 발표 전에 다시 조회할 수치.
- 발표자가 소리 내어 읽어 보고 자기 말이 아닌 문장을 고치라는 안내. 이 단계는 대신할 수 없다.
